# UC-02 ระงับบัตรและคืนเงินนักเรียนที่ย้ายออก

**Summary:** UC-02 ระงับบัตรและคืนเงินนักเรียนที่ย้ายออก
**Component:** `student-account`
**Story points:** ?
**Epic:** ยังไม่ระบุ

## User story

ในฐานะผู้ปกครองหรือสตาฟโรงเรียนที่ได้รับอนุญาต

ฉันต้องการระงับ/ปลดระงับบัตร และคืนเงินนักเรียนที่ย้ายออก

เพื่อป้องกันบัตรที่หายถูกนำไปใช้และคืนยอด Wallet ให้ถูกต้องเมื่อนักเรียนออกจากโรงเรียน

## กฎทางธุรกิจ

- การอายัดชั่วคราวเปลี่ยนสถานะเป็น `suspended`; ปลดกลับเป็น `active` ได้ตามสิทธิ์
- เมื่อ Parent รายงานว่าบัตรหาย เปลี่ยนสถานะเป็น `lost`; บัตร `lost` ต้องออกบัตรใหม่ ไม่ปลดกลับมาใช้
- Parent จัดการได้เฉพาะนักเรียนที่ตนมีสิทธิ์ดูแล; Staff ต้องมีสิทธิ์จัดการบัตร/คืนเงิน
- คืนเงินได้ไม่เกินหนึ่งครั้ง; ยอดบวกคืนเต็มจำนวน, ยอดศูนย์ปิดบัตรโดยไม่สร้างรายการคืนเงินศูนย์บาท
- การคืนเงินและปิดบัตรต้องไม่มีผลเพียงบางส่วน

## Acceptance criteria

| รหัส AC | Given | When | Then |
|---|---|---|---|
| **AC2.1a** | Parent แจ้งว่าบัตรของนักเรียนที่ตนดูแลหาย | Parent กดอายัดใน Parent Mobile App | สำเร็จ (`200 OK`): บัตรเป็น `lost` และชำระเงินไม่ได้ |
| **AC2.1b** | Parent แจ้ง Staff ให้ช่วยระงับบัตรโดยไม่ได้ระบุว่าบัตรหาย | Staff กดระงับใน Web Admin | สำเร็จ (`200 OK`): บัตรเป็น `suspended` และชำระเงินไม่ได้ |
| **AC2.2** | นักเรียนย้ายออกและ Wallet มี `250.00` บาท | Staff กดคืนเงิน | สำเร็จ (`200 OK`): บัตร `deactivated`, สร้าง `REFUND` `250.00` บาท, Wallet เป็น `0.00` บาท |
| **AC2.3** | บัตร `suspended` ถูกกู้คืนและผู้เรียกเป็น Parent ที่ผูกกับนักเรียนหรือ Staff ที่ได้รับอนุญาต; บัตรไม่ใช่ `lost`/`deactivated` | ผู้เรียกปลดระงับผ่านช่องทางที่ได้รับสิทธิ์ | สำเร็จ (`200 OK`): บัตรเป็น `active` |
| **AC2.4** | ผู้เรียกไม่ login หรือไม่มีสิทธิ์ Parent-Student/Staff | ผู้เรียกอายัด ปลดระงับ หรือคืนเงิน | ปฏิเสธ (`401 AUTHENTICATION_REQUIRED` หรือ `403 FORBIDDEN`); ไม่มีการเปลี่ยนข้อมูล |
| **AC2.5** | Student ID หรือ Card ID ไม่มีอยู่ | ผู้เรียกส่งคำขอ | ปฏิเสธ (`404 STUDENT_NOT_FOUND` หรือ `404 CARD_NOT_FOUND`); ไม่มีการเปลี่ยนข้อมูล |
| **AC2.6** | เคยคืนเงินนักเรียนย้ายออกสำเร็จแล้ว | Staff ขอคืนเงินซ้ำ | ปฏิเสธ (`409 REFUND_ALREADY_PROCESSED`); ไม่คืนเงินและไม่สร้างรายการซ้ำ |
| **AC2.7** | นักเรียนย้ายออกและ Wallet เป็น `0.00` บาท | Staff กดคืนเงิน/ปิดบัญชี | สำเร็จ (`200 OK`): บัตร `deactivated`, Wallet เป็นศูนย์ และไม่สร้าง `REFUND` ศูนย์บาท |

## นอกขอบเขต

- การออกบัตรทดแทนกรณีบัตร `lost` อยู่ใน UC-01
- การรับ/โอนเงินจริงและเชื่อม payment gateway สำหรับคืนเงิน
- การสร้างบัญชีและผูกความสัมพันธ์ Parent-Student

## คำถามที่ต้องตอบ

- การอายัด/ปลดระงับซ้ำควรเป็น no-op หรือ error?
- การคืนเงินต้องรอจัดการรายการ Offline ที่ยังไม่ Sync หรือไม่?
- ต้องเก็บหลักฐานช่องทางคืนเงินและ audit ใดบ้าง?
- ควรแยกงานอายัดออกจากงานคืนเงินหรือไม่ เพราะ UC-02 มี 8 AC และรวมสองความสามารถคนละ flow?

## Sub-tasks (ร่าง)

- `Spec: รีวิว UC-02 และ AC2.1a–AC2.7`
- `Spec: เพิ่ม endpoint ปลดระงับและกำหนด error response (AC2.1a–AC2.7)`
- `DB: เพิ่มสถานะ lost และป้องกันการคืนเงินซ้ำ (AC2.1a, AC2.2, AC2.6, AC2.7)`
- `Domain: บังคับ state transition ของบัตรและกฎคืนเงิน (AC2.1a–AC2.3, AC2.6–AC2.7)`
- `App: ประสานสิทธิ์ Parent-Student/Staff และตรวจเป้าหมาย (AC2.4–AC2.5)`
- `Infra: บันทึกสถานะบัตรและรายการคืนเงินแบบ atomic พร้อม PostgreSQL tests (AC2.1a–AC2.2, AC2.6–AC2.7)`
- `HTTP: ตรวจสิทธิ์และ map error ตาม OpenAPI (AC2.4–AC2.5)`
- `E2E: ทดสอบ freeze, unfreeze และ refund ผ่านช่องทางผู้ใช้ (AC2.1a–AC2.7)`
