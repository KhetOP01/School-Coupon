# UC-02: ระงับบัตรและคืนเงินนักเรียนที่ย้ายออก

> สถานะ: ร่างเพื่อรีวิว AC ก่อนเริ่มออกแบบ Database/API
> Bounded context: `student-account` (ระดับ `full`)
> แหล่งที่มา: [PRD](../../product_requirement_document_prd.md), UC-02 และ BR-CARD-04
> AC2.3–AC2.7 เป็น AC เพิ่มเติมที่ผู้ใช้อนุมัติสำหรับฉบับร่างนี้

## ผู้ใช้งาน

- ผู้ปกครองที่ยืนยันตัวตนและมีสิทธิ์ดูแลนักเรียน ผ่าน Parent Mobile App
- Staff ที่ยืนยันตัวตนและมีสิทธิ์จัดการบัตร/การย้ายออก ผ่าน Web Admin

## เงื่อนไขก่อนเริ่ม

- การอายัดต้องระบุนักเรียนหรือบัตรที่มีอยู่ในระบบ
- Parent ดำเนินการได้เฉพาะนักเรียนที่ตนมีความสัมพันธ์ดูแล
- การคืนเงินทำได้โดย Staff สำหรับนักเรียนที่ย้ายออก
- การคืนเงินต้องอ้างอิงยอด Wallet ของนักเรียน ณ เวลาทำรายการ

## ขั้นตอนหลัก

### อายัด/ระงับบัตร

1. Parent แจ้งบัตรหายและกดอายัดในแอป หรือ Parent แจ้ง Staff ให้ช่วยระงับบัตร
2. ระบบตรวจสอบตัวตน สิทธิ์ของผู้เรียก และบัตรเป้าหมาย
3. เมื่อ Parent แจ้งว่าบัตรหาย ระบบเปลี่ยนสถานะเป็น `lost`; เมื่อ Staff ระงับบัตรตามคำขอ ระบบเปลี่ยนสถานะเป็น `suspended`
4. ระบบปฏิเสธการใช้บัตรทั้งสถานะ `lost` และ `suspended` ในการชำระเงิน

### ปลดระงับบัตร

1. Parent ที่มีสิทธิ์ดูแลหรือ Staff ที่ได้รับอนุญาตเลือกปลดระงับบัตรที่ถูกกู้คืน
2. ระบบอนุญาตให้เปลี่ยน `suspended` กลับเป็น `active` เมื่อผ่านการตรวจสิทธิ์
3. บัตร `lost` ไม่สามารถปลดกลับเป็น `active`; ต้องออกบัตรใหม่ตาม UC-01

### คืนเงินเมื่อย้ายออก

1. Staff ค้นหานักเรียนที่ย้ายออกและตรวจยอด Wallet
2. ระบบคืนยอดคงเหลือให้เป็นรายการ `REFUND`, เปลี่ยนบัตรเป็น `deactivated` และทำให้ยอด Wallet เป็นศูนย์
3. หากยอด Wallet เป็นศูนย์อยู่แล้ว ระบบปิดบัตรได้โดยไม่สร้างรายการคืนเงินจำนวนศูนย์
4. ระบบป้องกันไม่ให้คำขอคืนเงินซ้ำทำให้เกิดการจ่ายหรือบันทึกรายการซ้ำ

## กฎทางธุรกิจ

- การระงับชั่วคราวใช้สถานะ `suspended`; ปลดกลับเป็น `active` ได้เมื่อบัตรถูกกู้คืนและผู้เรียกมีสิทธิ์
- เมื่อ Parent รายงานว่าบัตรหาย สถานะเป็น `lost` ทันที; บัตร `lost` ใช้ชำระเงินหรือปลดกลับเป็น `active` ไม่ได้
- Staff ที่ช่วย Parent ระงับบัตรโดยไม่ได้ยืนยันว่าบัตรหาย ให้ตั้ง `suspended`
- Parent จัดการได้เฉพาะนักเรียนที่ตนมีสิทธิ์ดูแล
- คืนเงินนักเรียนย้ายออกได้ไม่เกินหนึ่งครั้ง; การลองซ้ำต้องไม่เพิ่มยอดหรือสร้าง `REFUND` ซ้ำ
- ยอด Wallet ที่มากกว่าศูนย์คืนเต็มจำนวนตามยอดจริง แล้วเหลือ `0.00`; ถ้ายอดเป็นศูนย์ให้ปิดบัตรโดยไม่สร้างรายการ `REFUND` จำนวนศูนย์
- การคืนเงินและการปิดบัตรต้องไม่ทำให้เกิดผลเพียงบางส่วน; คำขอที่ถูกปฏิเสธต้องไม่เปลี่ยน Wallet หรือสถานะบัตร

## Acceptance criteria

| รหัส AC | Given | When | Then |
|---|---|---|---|
| **AC2.1a** | Parent ทราบว่าบัตรของนักเรียนที่ตนดูแลหาย | Parent กดอายัดใน Parent Mobile App | สำเร็จ (`200 OK`): สถานะบัตรเป็น `lost` ทันทีและใช้ชำระเงินไม่ได้ |
| **AC2.1b** | Parent แจ้ง Staff ให้ช่วยระงับบัตร | Staff กดระงับใน Web Admin โดยยังไม่ได้ระบุว่าบัตรหาย | สำเร็จ (`200 OK`): สถานะบัตรเป็น `suspended` ทันทีและใช้ชำระเงินไม่ได้ |
| **AC2.2** | นักเรียนย้ายออกและมียอด Wallet `250.00` บาท | Staff กดคืนเงินใน Web Admin | สำเร็จ (`200 OK`): บัตรเป็น `deactivated`, มี `REFUND` `250.00` บาท, ยอด Wallet เป็น `0.00` บาท |
| **AC2.3** | บัตรถูก `suspended` และผู้เรียกเป็น Parent ที่ผูกกับนักเรียนหรือ Staff ที่ได้รับอนุญาต; บัตรไม่ได้เป็น `lost` หรือ `deactivated` | ผู้เรียกปลดระงับบัตรผ่านช่องทางที่ได้รับสิทธิ์ | สำเร็จ (`200 OK`): สถานะบัตรเป็น `active` และสามารถใช้ชำระเงินได้ |
| **AC2.4** | ผู้เรียกไม่ได้ยืนยันตัวตน หรือไม่มีสิทธิ์ดูแลนักเรียน/ไม่มีสิทธิ์ Staff | ผู้เรียกพยายามอายัด ปลดระงับ หรือคืนเงิน | ปฏิเสธ (`401 AUTHENTICATION_REQUIRED` หรือ `403 FORBIDDEN`); ไม่มีการเปลี่ยนข้อมูล |
| **AC2.5** | Student ID หรือ Card ID ที่ระบุไม่มีอยู่ในระบบ | ผู้เรียกส่งคำขอจัดการบัตรหรือคืนเงิน | ปฏิเสธ (`404 STUDENT_NOT_FOUND` หรือ `404 CARD_NOT_FOUND`); ไม่มีการเปลี่ยนข้อมูล |
| **AC2.6** | มีการคืนเงินนักเรียนย้ายออกและบันทึกผลสำเร็จแล้ว | Staff ส่งคำขอคืนเงินซ้ำ | ปฏิเสธ (`409 REFUND_ALREADY_PROCESSED`); ไม่คืนเงินหรือสร้างรายการซ้ำ |
| **AC2.7** | นักเรียนย้ายออกและยอด Wallet เป็น `0.00` บาท | Staff กดคืนเงิน/ปิดบัญชีใน Web Admin | สำเร็จ (`200 OK`): บัตรเป็น `deactivated`, Wallet คง `0.00` บาท และไม่สร้าง `REFUND` จำนวนศูนย์ |

## นอกขอบเขต

- การออกบัตรใหม่หลังบัตรเดิมถูกระบุว่า `lost` อยู่ใน UC-01
- การเติมเงินและการปรับยอด Wallet จากรายการ Offline อยู่ใน UC-03 และ UC-05
- การคืนเงินเป็นเงินสด/โอนเงินจริงและการเชื่อม payment gateway ไม่ได้ระบุไว้ใน AC ของ UC-02
- การสร้างบัญชี, Login และการผูก Parent-Student เป็นกติกา identity แยกต่างหาก

## คำถามที่ต้องตอบ

- ถ้า Parent/Staff ส่งคำขออายัดบัตรที่ `suspended` อยู่แล้ว หรือปลดบัตรที่ `active` อยู่แล้ว ควรเป็น no-op สำเร็จหรือ error?
- ถ้ามีรายการ Offline รอ Sync ขณะ Staff คืนเงิน/ปิดบัตร จะระงับการคืนเงินหรือจัดการรายการที่มาทีหลังอย่างไร?
- หลักฐานการคืนเงินให้ Parent (โอน/เงินสด/ช่องทางอื่น) และ audit ผู้ดำเนินการต้องบันทึกที่ใด?
- ใช้ `403 FORBIDDEN` รหัสเดียวกับ Parent ที่ไม่ได้ผูกและ Staff ที่ไม่มี role หรือแยก error code ตามเหตุผล?
- PRD รวมการอายัดบัตรกับคืนเงินย้ายออกไว้ใน UC เดียว; ต้องการแยก Story/แผนส่งมอบเป็นงานอายัดและงานคืนเงินหรือไม่?

## API ที่เกี่ยวข้อง

- `PATCH /parent/cards/:id/freeze` ตาม PRD; เปลี่ยนเป็น `lost` เมื่อ Parent แจ้งว่าบัตรหาย
- `PATCH /admin/cards/:id/freeze` ตาม PRD; ใช้ `suspended` สำหรับการระงับชั่วคราว
- `POST /admin/students/:id/refund` ตาม PRD
- Endpoint สำหรับปลดระงับและ error response ของ AC ที่เพิ่มเป็นข้อเสนอ ต้องกำหนดใน `openapi.yaml` หลังรีวิว
