# UC-04: ผู้ปกครองตั้งวงเงินใช้จ่ายรายวัน

> สถานะ: ร่างเพื่อรีวิว AC ก่อนออกแบบ Database/API
> Bounded context: `student-account` (ระดับ `full`)
> แหล่งที่มา: [PRD](../../product_requirement_document_prd.md), UC-04 และ BR-LIMIT-01
> AC4.2–AC4.5 เป็นข้อเสนอเพิ่มเติม; ยังไม่ได้เพิ่มลง PRD

## ผู้ใช้งาน

ผู้ปกครองที่ยืนยันตัวตนและมีสิทธิ์ดูแลนักเรียน ผ่าน Parent Mobile App

## เงื่อนไขก่อนเริ่ม

- นักเรียนและบัญชีของนักเรียนมีอยู่ในระบบ
- ผู้ปกครองมีสิทธิ์ดูแลนักเรียนคนนั้น
- ระบบทราบวงเงินปัจจุบันและรับค่าวงเงินใหม่จากผู้ปกครอง

## ขั้นตอนหลัก

1. Parent เลือกนักเรียนและระบุวงเงินใช้จ่ายรายวันใหม่
2. ระบบตรวจสอบตัวตน สิทธิ์ดูแลนักเรียน และรูปแบบข้อมูลวงเงิน
3. ระบบบันทึกวงเงินใหม่เป็น `next_daily_limit`
4. วงเงินปัจจุบันยังใช้ต่อจนถึงวันถัดไป เวลา 00:00 น. แล้วจึงเริ่มใช้วงเงินใหม่
5. ระบบแจ้งผลการตั้งค่าวงเงินให้ Parent

## กฎทางธุรกิจ

- การเปลี่ยนวงเงินมีผลในวันถัดไป เวลา 00:00 น. เสมอ (BR-LIMIT-01)
- การตั้งค่าใหม่ระหว่างวันไม่เปลี่ยนวงเงินที่มีผลในวันนั้น
- วงเงินมีผลกับรายการชำระทั้ง Online และ Offline
- PRD ยังไม่กำหนดช่วงค่าต่ำสุด/สูงสุดหรือความละเอียดทศนิยมที่ยอมรับ

## แนวทางออกแบบตาม DDD (ข้อเสนอเพื่อรีวิว)

- **Bounded Context และภาษาธุรกิจ:** `DailyLimit` และความสัมพันธ์ผู้ปกครอง-นักเรียนเป็นแนวคิดของ `student-account`; ใช้ `current_daily_limit`, `next_daily_limit` และ “มีผลวันถัดไป” อย่างสม่ำเสมอ
- **Aggregate และ invariant:** `Wallet` เป็น aggregate root candidate ตาม context map ซึ่งอาจคุมวงเงินปัจจุบันและวงเงินที่รอมีผล; การตั้งวงเงินต้องผ่านพฤติกรรมของ root เพื่อไม่ให้คำขอแก้ค่า current limit โดยตรง
- **Value Objects:** `DailyLimitAmount` และวันที่/เวลามีผลเป็น value object candidates; ต้องกำหนดหน่วยเงิน, ความละเอียด, timezone และการแทนค่าวันที่มีผลก่อนทำให้เป็นโมเดลถาวร
- **Application และ ports:** use case โหลด aggregate ของนักเรียน, ตรวจ Parent-Student access, เรียกพฤติกรรมตั้งค่าวงเงิน แล้วบันทึกผล; ตรวจสิทธิ์ใช้สัญญาที่ประกาศไว้ ไม่ย้ายกฎการมีผลวันถัดไปไปไว้ใน application service
- **ขอบเขตข้าม context:** authorization อาศัย identity จาก `school-configuration`, ส่วน `student-account` เป็นเจ้าของการตัดสิน Parent-Student relationship; `payments` อ่านวงเงินผ่าน public contract เพื่อบังคับใช้ ไม่ import model ภายใน
- **ชั้น HTTP/Infrastructure:** HTTP ตรวจรูปแบบ/ชนิดข้อมูลและ map error; repository ของ `student-account` โหลดและบันทึก aggregate โดยไม่เปิดเผย row/schema เป็น API response
- **ประเด็นยังไม่ตัดสิน:** วิธีเลื่อน `next_daily_limit` ไปเป็น current, timezone, การตั้งหลายครั้งในวันเดียว และช่วงค่าที่อนุญาตยังต้องตกลงก่อนออกแบบ state transition และ persistence

## Acceptance criteria

| รหัส AC | Given | When | Then |
|---|---|---|---|
| **AC4.1** | วงเงินปัจจุบันคือ `100.00` บาท/วัน | Parent ปรับวงเงินเป็น `150.00` บาท/วันระหว่างวัน | สำเร็จ (`200 OK`): บันทึก `next_daily_limit = 150.00`; วงเงินวันนี้คงเป็น `100.00` และวงเงินใหม่มีผลวันถัดไปเวลา 00:00 น. |
| **AC4.2** *(เสนอ)* | คำขอไม่มีวงเงิน หรือส่งวงเงินที่ไม่ใช่จำนวนเงินที่ระบบอ่านได้ | Parent ส่งคำขอตั้งวงเงิน | ปฏิเสธ (`400 INVALID_DAILY_LIMIT`); ไม่เปลี่ยนวงเงินปัจจุบันหรือวงเงินที่รอมีผล |
| **AC4.3** *(เสนอ)* | Student ID ที่ระบุไม่มีในระบบ | Parent ส่งคำขอตั้งวงเงิน | ปฏิเสธ (`404 STUDENT_NOT_FOUND`); ไม่เปลี่ยนข้อมูล |
| **AC4.4** *(เสนอ)* | ผู้เรียกไม่ได้ยืนยันตัวตน หรือไม่มีสิทธิ์ดูแลนักเรียน | ผู้เรียกส่งคำขอตั้งวงเงิน | ปฏิเสธ (`401 AUTHENTICATION_REQUIRED` หรือ `403 PARENT_STUDENT_ACCESS_DENIED`); ไม่เปลี่ยนข้อมูล |
| **AC4.5** *(เสนอ)* | Parent ส่งคำขอตั้งวงเงินค่าเดิมซ้ำในวันเดียวกัน | ระบบรับคำขอซ้ำ | สำเร็จ (`200 OK`) แบบ idempotent; `next_daily_limit` คงค่าเดิมและ `current_daily_limit` ไม่เปลี่ยน |

## นอกขอบเขต

- การซื้อสินค้าและการบังคับใช้วงเงินขณะชำระเงินอยู่ใน UC-05
- การผูก Parent กับ Student และการยืนยันตัวตนเป็นข้อกำหนด identity แยกต่างหาก
- การตั้งค่าวงเงินเติมเงินขั้นต่ำ/สูงสุดเป็นคนละ policy กับวงเงินใช้จ่ายรายวัน

## คำถามที่ต้องตอบ

- วงเงินต่ำสุด/สูงสุดและความละเอียดทศนิยมที่อนุญาตคือเท่าใด?
- ถ้า Parent เปลี่ยนวงเงินหลายครั้งในวันเดียว คำขอล่าสุดแทนค่าที่รอมีผลก่อนหน้าหรือไม่?
- การเปลี่ยนวันที่และเวลา 00:00 น. อ้างอิง timezone ใด?
- เมื่อผู้ปกครองไม่มีสิทธิ์ดูแลนักเรียน ควรตอบ `403` หรือซ่อนการมีอยู่ของนักเรียนด้วย `404`?

## API ที่เกี่ยวข้อง

- `PATCH /parent/students/:id/daily-limit` ตาม traceability matrix ใน PRD
- Error code และ response ของ AC4.2–AC4.5 เป็นข้อเสนอ; ต้องรีวิวและระบุใน `openapi.yaml` ก่อน implementation
